# テスト規約

## 目的

ユーザー体験を損なう致命的な不具合の検出力を維持しつつ、常設テストの実行・保守コストを最小限に抑える。

## テストの採否基準

カバレッジや件数を目標にしてはならない。「そのテストがないと致命的な不具合を見逃すか」のみで採否を判断する。

### テストを書く対象
- 壊れるとユーザー体験が破綻する、中核的なユニットのロジック

### テストを書かない対象（除外するもの）
- 型システムや外部ライブラリがすでに保証している挙動
- Lintやビルドなど、他の自動チェックで検出できる不具合
- 実画面の目視確認で済むUIの見た目（配置・余白・色・折り返しなど）
- 同一ロジックの過剰なケース分けや、同じ検証結果の反復
- テスト用のダミーコード自体の検証

## テストの実装ルール

- **1テスト1検証**: 検証内容を一文で端的に説明できる粒度にする。
- **期待値は仕様から導く**: 実装コードの判定関数をテスト内で再利用したり、現在の出力値を盲目的にコピーしたりしない。
- **実物を動かす**: 本体の処理をテスト内に複製せず、実際の入力と出力で検証する。
- **HTML検証は要点に絞る**: DOM全体の完全一致ではなく、ユーザー体験に影響する重要な要素やテキストのみを検証する。
- **モックの禁止**: 自作モジュールもライブラリも実物を呼び出す。
  - モックは実装との乖離やモック自体の保守コストを生むため、原則使用しない。

## ディレクトリ構成

- テストは各パッケージの `tests/unit/` 配下に置き、`src/` のディレクトリ構造をそのままミラーする。
  - 実装が削除された際、不要になったテストを機械的に特定できるようにするため。
- テスト共通のヘルパー関数は `tests/utils/` に置く。

```text
apps/{app}/tests/
├── unit/   # src/ と同じ階層でテストを配置
└── utils/  # テスト専用ユーティリティ
```

## 実行方針

- テストランナーに依存しない普遍的なテストを書く。
- 自動検査は、`just ci-local` などの単一コマンドで一括実行（テスト・Lint・型検査・ビルド）できるようにする。
- CI実行時間を短縮したい場合は、小手先の並列化ではなく「不要なテストの削除・統合」および「処理の重複排除」で解決する。
