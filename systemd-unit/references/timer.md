# 定期実行

| 種類 | 書き方 |
|---|---|
| 時刻に意味がある | `OnCalendar=` |
| 間隔だけに意味がある | `OnBootSec=` + `OnUnitActiveSec=` |

`OnBootSec` を併記するのは、これが無いと起動直後の 1 回目が `OnUnitActiveSec` の間隔ぶん
遅れるため。

## 常に付けるもの

`Persistent=true`。ラップトップは頻繁に閉じられ、電源が落ちる。これが無いと、予定時刻に
電源が入っていなかった回は単に消滅する。付けておけば、起動時に「前回から間隔が過ぎている」と
判断して走る。

**この指示子が効くのは `OnCalendar=` を使う timer だけである。** `OnUnitActiveSec=` の
間隔型に書いても何も起きないため、間隔型で取りこぼしを避けたい場合は `OnBootSec=` で
起動直後の 1 回を確保する方法しかない。

## 付ける場面が限られるもの

`RandomizedDelaySec` は外部サービスを叩くものにのみ付ける。定時ちょうどのアクセスが
そのサービスに集中するのを避けるための機能であり、ローカル完結の処理に付けても
起動を遅らせるだけになる。

`Persistent=true` と併用する場合、取りこぼしを回収する起動直後の実行も
`RandomizedDelaySec` の遅延を受ける。両者は独立していない。

`AccuracySec` は書かない。既定の 1 分の遊びは、systemd が複数の timer をまとめて起動して
CPU の起床回数を減らすためのものであり、ラップトップではバッテリーに効く。

## 命名

service と timer は同じ語幹にする。同名なら timer が同名の service を起こすため、`Unit=` 行が
不要になる。

timer に起こされる service には `[Install]` を書かない。書いて有効化すると、そのバッチが
起動時にも走る。スケジュールを与えているのは timer であり、有効化すべきは timer の方である。
