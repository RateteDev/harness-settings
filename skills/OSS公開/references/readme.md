# README

公開するリポジトリのREADMEは、初見の人が何のためのものか、どう試せるかを把握できる状態にする。

## 構成

- タイトルの直後に用途と対象が一文で書かれ、前提・導入・最小の実行例へつながっている。
- できることが絵文字付きの箇条書きで並んでいる。
  書かれたコマンドと動作は、対象リポジトリで確認されている。
- 利用者が最初に読む節は短い段落と箇条書きで構成され、1段落は2文までである。
- 機能や導入経路が複数あるときは最短の入口だけが示され、詳しい説明は既存の文書へのリンクになっている。
  見出しや機能一覧は、利用者が試すのに要る分だけある。
- 入手と利用が分かれ、「インストール」「使い方」の順に節がある。
- 性質の違う導線（例：ライブラリの導入と同梱スキルの配置）は別の節に分かれている。
- リポジトリの目的が完成品の配布なら、開発節は無く、ビルドやテストの手順はソースや別文書にある。
- 利用者に影響する注意点は「注意点」の見出しに短くまとまっている。
  書くのは対応外の形式と自動で止まる条件だけで、内部の上限値は列挙しない。
- コマンド例では、各コマンド行の直前にその行で何が起きるかが短く書かれている。
  結果の補足は同じコメントの括弧内に収まっている。

## 図と画像

- 図は画像で示されており、Mermaidは使われていない。
- 操作の流れを示す図は、実際の入力・操作・出力が追える具体的な画面や成果物を描き、その表記がソースと一致している。
- 図の流れは、本文か代替テキストからも分かる。
- GUIや視覚的な操作があるアプリでは、実画面のスクリーンショットが置かれている。
  画像を用意できない場合はユーザーへ依頼し、READMEは実在する画像だけを参照している。

## ヒーロー

- ヒーローは中央寄せで、ワードマーク・バッジ・言語リンクの順に並んでいる。
- ワードマークは、文字をアウトライン化したSVGが`assets/`にあり、`<picture>`でlight/darkを出し分けている。
  環境のフォントに表示を左右させないためである。
- バッジは実際の配布先や状態を表し、文言は公開前にユーザーの確認を得ている。
- 言語リンクやバッジが複数あるときは1行に2件ずつ並び、狭い画面でも崩れないことを確かめている。

## ライセンス

- ライセンスは公開前に決まり、ライセンスファイルがある。
  未決定なら公開前にユーザーへ確認する。
- ライセンスは上部のバッジで状態が示され、下部の「ライセンス」見出しのリンクから実際の条件へ案内されている。

## 多言語

- 既定言語版がリポジトリのルートの`README.md`に、英語版が`docs/readme/README.en.md`にある。
  GitHubは`.github/`・ルート・`docs/`の直下にあるREADMEだけをリポジトリの顔として表示するためである。
- 双方の先頭に`{既定言語} ・ English`の言語リンクが並んでいる。

## 仕上がり

- GitHubのmarkdownレンダリングでの表示か画像への描き出しで、レイアウトの崩れが無いことを確かめている。
- [見本](output-example.md)と並べて写す観点を点検し、届かない観点は直されている。
- プラットフォーム差などで写せない観点は、残課題としてユーザーへ伝えている。
