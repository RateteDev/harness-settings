# AGENTS.md規約

## 目的

指示の散逸による重複や矛盾を防ぎ常に単一の正本（Single Source of Truth）を保つ。
プロジェクト共通の指示は`AGENTS.md`に、マシン固有の指示は`AGENTS.md.local`に切り分けて管理する。

## 配置ルール

- **指示の正本化**: プロジェクトの指示は`AGENTS.md`を正本とし、同じ規則を複数箇所に重複して書かない。
- **適用範囲別の配置**:
  - **リポジトリ共通 (`AGENTS.md`)**: プロジェクト直下に配置しGitで管理する。マシン依存の値（絶対パス、個別ホスト名、unit名など）は書かず一般的な名称を用いる。
  - **ローカル環境依存 (`AGENTS.md.local`)**: プロジェクト直下に配置し、必ず`.gitignore`に含める。稼働ユニット、絶対パス、ローカルツール等の環境固有情報を記載する。
    - ※実行環境（ハーネス）は作業ディレクトリ直下の`AGENTS.md.local`のみを起動時に読み込み、親ディレクトリへは遡らないため。
- **グローバル設定**: ユーザー共通の`AGENTS.md`を編集する場合は、必ずユーザーと合意の上で行う。
- **書式例**: `AGENTS.md.local`の形式は[実例](examples/my-r2.AGENTS.md.local)に準拠する。

## 章構成

`AGENTS.md`は「動機から規則へ」進む以下の5章で構成する（章名・順序・構成は[例](examples/my-r2.AGENTS.md)に準拠）。

1. **問題**: 開発・運用で解決したい課題や背景。
2. **方針**: 解決に向けた基本方針。
3. **前提**: 方針を成立させるためのコード外の条件。
4. **配備方法**: デプロイや実行手順の要点（ホスト直接・バイナリ・Docker等。不要なリポジトリでは省略可）。
5. **規則**: 常時遵守すべき制約の表。

### 作成手順と注意点
- **問題・方針・前提**: ソースコードだけでは判断できないため、リポジトリ所有者へのヒアリング結果を基に記載する。
- **規則表**: 事前にコードや変更履歴を調査し確認できた事実のみを記載する。
- **リポジトリ固有の記述**: 例文の内容をそのまま流用せず対象リポジトリ固有の事実と制約のみを記載する。
- **既存の英語ファイル**: 既存の`AGENTS.md`が英語で書かれている場合は流用せず、調査とヒアリングに基づいてゼロから日本語で書き直す。

## 規則表の書き方

- **形式**: 「規則 | 理由」の2列テーブル。勝手な例外判断を防ぐため全行に必ず理由を添える。
- **文末**: 規則は「〜する。」理由は「〜のため。」で統一して言い切る。
- **記載対象**:
  - テストやCI（コンパイラ・リンター）では検知できない、人間やエージェントが意識して守るべき制約のみを載せる。
  - ディレクトリ一覧や設定ファイルから自明な構成情報の転記は避ける。
  - コードやアーキテクチャ自体で強制される不変条件は規則表ではなく「問題」または「方針」に書く。
- **禁止事項**: 否定形（〜しない）で書く場合は必ず代替手段をセットで記載する。
- **外部参照**: 外部ドキュメントを参照させる場合はパスと「いつ参照すべきか」を明記する。

## 文体・記法

- 日本語の簡潔な平叙文を用い比喩や抽象的な表現を避けて事実と規則を端的に書く。
- 識別子・ファイルパス・固有名詞は原語表記（英数字等）のまま記載する。
