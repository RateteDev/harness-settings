# パスキー

## ライブラリ

- `@simplewebauthn/server`と`@simplewebauthn/browser`を使う。
- Cloudflare Workersでの動作は公式に書かれていないため採用前に試す。

## 登録の設定

| 項目 | 値 |
|---|---|
| `user.id` | 個人情報を含まない32バイトの乱数 |
| `user.name`と`displayName` | 作成時はサービス名と作成日とし本登録の後に連絡先メールへ変える |
| `residentKey` | `required` |
| `userVerification` | `preferred` |
| `attestation` | `none` |

## 作成とサインイン

- 作成の時点で仮登録のアカウントを作り連絡先メールの確認へ進める。
- 本登録にしたら`signalCurrentUserDetails()`で名前を連絡先メールに変える。
- 確認したメールが既存のアカウントと重複したら仮登録を消し`signalUnknownCredential()`を呼ぶ。
- サインインは空の`allowCredentials`をボタンから渡しConditional UIは使わない。
- 未知の資格情報でサインインされたら`signalUnknownCredential()`を呼ぶ。
- サインインと削除のたびに`signalAllAcceptedCredentials()`を呼び空の一覧では呼ばない。
- Signal APIはFirefoxが未対応のため関数があるときだけ呼ぶ。

## 検証

- UVフラグのない応答は拒否する。
- 署名カウンタは同期されるパスキーが0を返し続けるため保存値と応答がともに0なら比べない。

## 管理画面

- パスキーごとにカードを出し名前と作成日時と最終利用日時と削除を置く。
- 名前はAAGUIDからFIDO Metadata Serviceで提供元を調べて付け、分からなければOSとブラウザの名前にする。
- `passkey-authenticator-aaguids`は2027年1月に空になるため使わない。
