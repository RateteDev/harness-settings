# ER図規約

## このスキルの目的

DDLや物理型をそのまま写したER図は、値の意味や運用上の補足を読み取れず、図ごとに部品の切り方も揃わない。
表記・網羅性・分割の規則を揃え、どの図でも同じ読み方でスキーマを追えるようにする。

## あるべき状態

### カラムの表記

- 型は物理型ではなく、格納される値の意味的型（例: `USER_ID`・`EMAIL`・`TEXT`）で書かれている。
- 型名などの命名・略記は、同一ドキュメント内で揃っている。
- NULL許容カラムは、型の末尾の`_NULL`（例: `DATE_NULL`）だけで表されている。
- カラムブロックを描いたテーブルには、全カラムが載っている。
- カラム末尾の`"..."`には、意味・運用上の補足が1行で書かれている。
  命名から意味が自明な列は空にしてある。
- 用語集（SSOT）がある場合、図中の語彙はそれに揃っている。

### 図の構成

- 冒頭に、カラムを持たないリレーション専用の図が1枚ある。
- 続く詳細図は、関連の強いテーブル群ごとに機能的凝集で分かれている。
- 各テーブルは、いずれか1つの詳細図だけにある。

### リレーション

- 外部キー制約の無い運用上の参照（論理FK）も線で描かれ、ラベルに「論理FK」とある。
- 自己参照は線ではなく、カラムの備考で表されている。
- 基底テーブルのミラーは、基底への1:1リレーションとして描かれている。
- 実装詳細の影テーブルは図に無い。

### 記述ルールセクション

- 出力ドキュメントに「記述ルール」を置く場合、そこにはスキーマに依存しない汎用的な説明だけがある。
- 記述ルールには「人間のみが編集／サブエージェントは読み取り専用」と明示されている。
