# README作成ガイドライン

公開リポジトリのREADMEを作成する際は、初見のユーザーが「何のためのものか」「どう試せるか」を即座に理解できる構成にします。

---

## 1. 構成と記述ルール

- **冒頭（導入）**
  - タイトル直後に「用途」と「対象ユーザー」を1文で明記する。
  - 続けて、前提条件・インストール・最小限の実行例を案内する。
  - 1段落は2文以内とし、箇条書きを活用して簡潔に書く。
- **機能一覧**
  - 主な機能は絵文字付きの箇条書きで記載する。
  - 記載するコマンドや挙動は、実際に対象リポジトリで動作確認する。
- **節の配置と順序**
  - 「インストール」→「使い方」の順に記載する。
  - 性質の異なる導線（例: ライブラリ本体の導入 / 同梱スキルの配置）は節を分ける。
  - 完成品を提供するリポジトリでは「開発手順（ビルド・テスト）」の節は作らず、別文書に分ける。
- **詳細への誘導**
  - 本文では最短の手順のみを示し、詳細な説明は外部ドキュメントへのリンクにとどめる。
- **コマンド例の表記**
  - 各コマンド行の直前に、実行内容を短いコメントで記述する（結果の補足は括弧内に記載）。
- **注意点**
  - 利用者に影響する「非対応の形式」や「自動停止する条件」のみを「注意点」節に簡潔にまとめる（内部仕様の数値などは記載しない）。

---

## 2. ヒーローエリアと画像

- **ヒーローエリアの構成（中央寄せ）**
  1. **ワードマーク**: 文字をアウトライン化したSVGを `assets/` に配置し、`<picture>` タグでライト/ダークモードを出し分ける。
  2. **バッジ**: 配布先や状態を示すバッジを配置する（文言は事前にユーザーへ確認）。
  3. **言語リンク**: 複数言語がある場合に配置する。
  ※ バッジやリンクが複数ある場合は1行に2件ずつ並べ、モバイル表示での崩れを防ぐ。
- **画像・スクリーンショットの利用**
  - Mermaidは使用せず、画像ファイルを使用する。
  - GUIアプリでは実際の操作画面のスクリーンショットを掲載する。
    画像がない場合はユーザーに提供を依頼し、存在しない画像パスは記述しない。
  - 図やスクリーンショットには、本文または代替テキスト（alt）で流れを説明する。

---

## 3. ライセンスと多言語対応

- **ライセンス**
  - 事前にライセンスを確定させ、ライセンスファイルを配置する（未決定の場合はユーザーに確認）。
  - 上部にステータスバッジを置き、下部の「ライセンス」節から該当ファイルへリンクする。
- **多言語対応**
  - **既定言語版**: リポジトリ直下の `README.md`
  - **英語版**: `docs/readme/README.en.md`
  - 双方の最上部に `{既定言語} ・ English` の形式で相互リンクを設置する。

---

## 4. 完成後の点検

1. **表示確認**: GitHubのプレビュー表示、または画像書き出しでレイアウト崩れがないか確認する。
2. **見本との比較**: [output-example.md](output-example.md) と照合し、不足している要素を修正する。
3. **未解決事項の報告**: 環境差などで対応できなかった項目は、残課題としてユーザーに報告する。
