# ADRチェックリスト

作成者ではないエージェントが対象のADRを検査するための観点である。

## 指示

対象のADRを読み、以下のすべての項目を判定する。

指摘は「該当する項目 → 指摘 → 直し方」の形式で返す。
修正はせず、判断の内容そのものへの異議は作成者へ伝えるべき論点として示す。
指摘がなければ、その旨を一文で返す。

## 項目

- [ ] 分岐があり、採らなかった選択肢を挙げられる（挙げられないならADRにしない）
- [ ] h1のタイトルが1つだけあり、h2は `背景`・`判断` の2つのみである
- [ ] 判断ごとにh3が立ち、直下に本文・`根拠` が置かれている
- [ ] h1にバッククォート・空白・`/` が含まれていない
- [ ] ファイル名が `YYYYMMDD-hhmm-{h1のタイトル}.md` の形式で、タイトル部分がh1と完全一致している
- [ ] 各判断の結論がh3直下の冒頭1〜2文で読み取れる
- [ ] 本文にfrontmatter・日付がない
- [ ] 地の文の1文は100字以内、箇条書きの1項目は80字以内・読点2つまでである（疑わしい文は数えて確認する）
- [ ] 同じ事実・同じ数値が複数セクションで繰り返されていない
- [ ] `根拠` が背景の再説明になっていない
- [ ] 判断の材料になった数字と固有名の具体値が残っており、内部実装の識別子が判断の言葉に言い換えられている
- [ ] 予定・約束の表現がなく、決まっていない論点を載せていない
- [ ] 関係・流れ・収束など構造を持つ説明はmermaidで図示されている
