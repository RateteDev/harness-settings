# スキルの書き方

スキルとはエージェントが「いつ実行し何を達成すべきか」を定義する指示書である。

## 記載基準

- **書く基準**：エージェントの出力精度に直結する情報のみを書く。
- **省く基準**：一般的な知識、コードや `--help` から取得できる仕様、自明な手順は書かない。
- **スキル間の参照禁止**：本文から他スキルを直接指定しない。依存関係の破損を防ぐため、スキルの選択は各スキルの `description` に委ねる。

## 本文の構成

文書は `# スキル名`（h1）で開始し、以下の `## 見出し`（h2）を順に配置する。
「このスキルの目的」以外は必要な項目のみを配置する。

1. **このスキルの目的**（必須）
   - 解決する課題と達成目標を1〜3文で簡潔に書く。
2. **あるべき状態**
   - 達成すべき状態を「〜する」と言い切りの箇条書きで書く。
   - 「〜している」という表現は完了済みと誤認するため避ける。
   - 完了確認の基準として機能させ別途チェックリストは作らない。
3. **守る順序**
   - 不可逆な手順や承認必須のステップがある場合のみ、理由を添えて番号付きリストで書く。
4. **手段**
   - 自力で生成困難なコマンド構文やパラメータ指定など、具体的な手法を書く。

## 表記ルール

- 常体（だ・である）を用い肯定文で書く。
- 1文を1行で書く（文の途中で改行しない）。
- マークダウンの強調記号は句点（。）の内側に閉じる。
- 長文の資料は `references/` に配置し、本文には参照タイミングのみを書く。

## Frontmatter（メタデータ）

| キー | 規則 |
|---|---|
| `name` | ディレクトリ名と完全一致させる。日本語64文字以内。 |
| `description` | 必須。エージェントが実行要否を判断できるよう、発動条件と概要を1024文字以内で具体的に書く。 |
| `metadata.user-review` | 人間によるレビュー完了状態（`true`・`false`）。スキルを更新したら必ず `false` に戻す。 |
| `metadata.labels` | 以下の3分類から該当するものを指定する。<br>・`規約`：満たすべき基準や制約<br>・`使い方`：CLIやAPIなどの操作手順<br>・`考え方`：設計方針や判断基準 |

※ スキルを一時的に無効化する場合は、ファイル名を `.SKILL.md` に変更する。

## ディレクトリ構成

| ディレクトリ | 用途 |
|---|---|
| `scripts/` | スキルが実行するスクリプト群（詳細は各スクリプトの `--help` に委ねる）。 |
| `templates/` | エージェントがコピーして使う成果物の雛形。 |
| `references/` | 特定の手順でのみ読み込む詳細資料。 |
