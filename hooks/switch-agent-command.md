# switch-agent-command

## いつ

三つの契機で動く。
一つ目はプラグインの起動時で、エージェントの一覧を取得し、切り替え用のコマンドを登録する。
二つ目はエージェントの構成が更新されたことを知らせるイベントを受け取ったときで、一覧を取得し直してコマンドの登録を再読み込みする。
三つ目は利用者がUIで登録済みのコマンドを実行したときで、実行元のセッションIDが取れる。

エージェントの一覧からは、各エージェントの識別子、表示名、任意の説明文、種別（サブエージェント専用、メイン、両用）、非表示かどうかが取れる。
切り替えの通知には、モデルの応答を起動しない擬似メッセージを会話へ差し込む能力が要る。

## 何をする

Web UIで、利用可能なエージェントの中から切り替え先を選んで、セッションのエージェントを切り替えられるようにする。
Web UIに組み込みの/agentコマンドは、エージェントを順番に切り替えるだけで、候補から選べなかった。
Web UIはコマンドの引数に候補を出す仕組みを持たないため、選べるエージェントごとに「agent/識別子」という名前のコマンドを一つずつ登録する。
利用者が/agent/と入力すると、メインのエージェントが候補として出る。

登録するのは、種別がサブエージェント専用でなく、かつ非表示でないエージェントだけである。
構成が変わったときは一覧を取得し直して再登録するので、追加や非表示への変更が候補に反映される。

コマンドを実行すると、そのセッションの現在のエージェントを指定のエージェントへ切り替え、続けて切り替えたことを日本語で述べる擬似メッセージを会話へ差し込む。
モデルを呼び出さずに切り替えられ、結果が画面に残る。

## 調整値と根拠

コマンド名の接頭辞は「agent/」で、候補にする条件は上記のとおりである。
数値の閾値や上限は持たない。
候補をメインのエージェントに絞ることがコミット履歴に記されている以外には、接頭辞と候補の条件を選んだ根拠、通知を日本語にした理由は、根拠の記載なし。

## 失敗時の扱い

起動時のエージェント一覧の取得に失敗した場合の扱いは、ソースに処理がなく、不明である。例外が伝わるとしても、プラグインの読み込み失敗になるかどうかは確認できない。

構成の更新を受け取った後の一覧の取得やコマンドの再読み込みに失敗したときは、原因を付けて標準エラーへ記録する。プラグインの終了処理による中断のときは記録しない。
会話や利用者への通知はなく、再読み込み前の登録が残るので、古い候補が表示され続ける可能性がある。
更新イベントの購読は、一度失敗すると終了し、それ以降の更新は反映されない。

コマンドの実行中にエージェントの切り替えが失敗したときは、擬似メッセージを差し込まずに例外が伝わる。利用者へどう表示されるかは不明である。
