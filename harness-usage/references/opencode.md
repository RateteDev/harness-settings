# OpenCode Go

`scripts/opencode-go-usage.sh`はOpenCode GoのAPIキーで`GET https://opencode.ai/zen/go/v1/usage`を呼び出す。ローリング5時間・週次・月次の各ウィンドウについて、正確なライブのサブスクリプション使用量とリセット時刻を返す。

キーは対話的に渡すか、コマンド実行時だけ`OPENCODE_GO_API_KEY`を設定する。設定ファイル、シェル履歴、スキル、チャットへキーを書かない。

```sh
OPENCODE_GO_API_KEY="$OPENCODE_GO_API_KEY" scripts/opencode-go-usage.sh
```

エンドポイントは公開されているGo APIリファレンスに記載されていない。変更された場合は、OpenCode Zen Consoleで最新の使用量を確認する。

## percent の読み方

`/v1/usage` が返す `percent` はモデル別の残量ではなく、アカウント共通の3ウィンドウ（5時間・週・月）に対する加算済み消費率である。`?model=` は無視される。`monthly` は月初ではなく請求サイクル基準のローリングで、`resetsAt` がそのままリセット時刻。

共通枠は1組だけで、モデルごとの消費は次の重みで加重される。

```
重み = プランの月間上限 ÷ そのモデルのドキュメント上の月間上限
quota消費 = 実際のドル消費 × 重み
```

記載上限がプラン月次の 1/4 なら 4.0×、1/2 なら 2.0×、等しければ 1.0×。コンソールのモデル別 `used / quota` 行は「共通枠 ÷ 重み」の内訳表示であり、別々の財布ではない。モデル名は頻繁に入れ替わるため、重みはドキュメントの月間上限から毎回算出する。

出典は公式ドキュメントではなく issue。式は #41391、一致は #45539 の実測値（`$3.0255×4 + $0.0668×2 = $12.24 → 102%`）で確認。#41391 には記載と食い違う内部重み（実測 1.52×）の報告があり、`costMultiplier` がドキュメントと同期していない可能性がある。食い違ったら実測を優先する。
