# 自作アプリ

## このスキルの目的

所有者1人のためのアプリを守るものに見合った最小の仕組みで作る。
複数の利用者に備えた表や画面は作らない。
他の人が使うようになったら[認証フロー設計](../認証フロー設計/SKILL.md)に従って作り直す。

## 基盤

Cloudflareに置きAPIは公開する。
Cloudflare Accessは使わない。
外部サービスの秘密はCloudflareにだけ置き端末には置かない。

## 所有者のログイン

所有者はパスキーだけでログインする。
最初のパスキーは早いもの勝ちで登録させ登録が済んだら初期設定の入口を閉じる。
復旧の手段は作らずログイン中のクライアントからパスキーを足せるようにする。
他人に先に登録されたときと全てのパスキーを失ったときはwranglerでDBの認証の表を空にして登録し直す。

## 環境のログイン

PCやエージェントやハーネスなど所有者のクライアント以外の相手を環境と呼ぶ。
環境は名前を添えて要求を出し所有者に通知が届く。
所有者がクライアントで承認するとコードが出てそのコードを環境で入力すると環境はログイン状態を受け取る。

承認待ちの要求は5件までとし10分で切れる。
コードはその要求にだけ使え5回間違えると要求ごと無効にする。
通知の手段はアプリごとに選び承認はクライアントでだけ行う。
メールで通知するときは承認画面へのリンクだけを載せる。

コードを入力できない環境にだけクライアントからAPIキーを発行する。

## ログイン状態

サーバーにはハッシュだけを置き最終利用日時は1日に1回だけ書き直す。
クライアントのログイン状態はログインから14日で切れる。
環境とAPIキーのログイン状態は期限を持たない。

Cron Triggersで毎日見回り30日使われていない環境とAPIキーを30日ごとに通知し自動では消さない。
クライアントに一覧を出し名前と登録日時と最終利用日時を示して1つずつ外せるようにする。

## 管理操作と確認

管理用の認証は作らない。
デプロイ後の確認はログインのいらない範囲で行う。
ログインした状態で確かめるときはログイン済みのクライアントをadbやブラウザの自動操作で動かす。
