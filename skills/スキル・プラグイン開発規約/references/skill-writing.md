# スキルの書き方

スキルとは、エージェントが「いつ作業を行い、どのような結果を達成すべきか」を定義する文書である。

## 記載基準

- **記載の要否**：「書かないとエージェントの出力精度が落ちるか」で判断する。
- **除外するもの**：一般的な知識、`--help` やコードから自力で読み取れる仕様、ゴールから自明な手順は書かない。
- **長さ**：構成を揃えるために本文を長くしない。
- **スキルの連携**：本文から他のスキルへ直接言及しない（破損検知が難しいため）。エージェントによるスキルの検出・選定は各スキルの `description` に委ねる。

## 本文の構成

文書は `# スキル名`（h1）で開始し、以下の `## 見出し`（h2）を順に配置する。
なお、「このスキルの目的」以外は**必要な場合のみ**設ける。

1. **このスキルの目的**（必須）
   - 解決する課題と達成目標を1〜3文で簡潔に書く。
2. **あるべき状態**
   - 満たすべきゴールを「〜する」と言い切る箇条書きで書く。
   - ※「〜している」と書くと、未作業でも完了済みと誤認するため避ける。
   - そのまま確認項目として使える形にし、別途チェックリストは作らない。
3. **守る順序**
   - 順序を崩すとリカバリー不能になる手順や、承認を挟む必要がある手順のみを、理由とともに番号付きリストで書く。
4. **手段**
   - コマンド書式やAPIパラメータなど、自力で導けない具体的な知識を書く。
   - 短い手順なら番号付きリストで書いてよい。

## 表記ルール

- 常体（だ・である）を用い、肯定文で書く。
- 1文を1行で書く（改行による誤解を防ぐため）。
- 強調（太字など）は句点（。）の前に閉じる。
- 長大なドキュメントは `references/` に配置し、本文には「どのタイミングで参照するか」のみを書く。

## Frontmatter（メタデータ）

| キー | 規則 |
|---|---|
| `name` | ディレクトリ名と完全一致させ、日本語64文字以内にする（システム間の識別子の不一致を防ぐため）。 |
| `description` | 必須。エージェントが利用可否を判定できるよう、1024文字以内で具体的に書く。 |
| `metadata.user-review` | 人間によるレビュー完了を示す真偽値。内容を更新したら必ず `false` に戻す。 |
| `metadata.labels` | 以下の3分類から、スキルの主目的に沿うものを指定する。<br>・`規約`：成果物や操作が満たすべき基準を定める<br>・`使い方`：特定のCLIやAPIの操作方法を定める<br>・`考え方`：設計や判断の拠り所を定める |

※ スキルを一時的に無効化する場合は、ファイル名を `SKILL.md` から `.SKILL.md` へ変更する。

## ディレクトリ構成

| ディレクトリ | 用途 |
|---|---|
| `scripts/` | スキルが呼び出すスクリプト群（使い方はスクリプト自身の `--help` で確認できるもの）。 |
| `templates/` | エージェントが複製して利用する成果物のテンプレート。 |
| `references/` | 特定の作業フェーズでのみ参照する長文資料。 |
