# スキルの書き方

スキルは、エージェントが「いつ・なぜ」ある作業を選び、作業中に何を守るかを伝える文書である。`SKILL.md`はエージェントへ毎回注入され、読むたびにトークンを消費して判断へ影響する。載せるのは、エージェントが持たない知識と、エージェントが従うべき規則だけに絞る。

## 載せる内容

`SKILL.md`に置くのは、次の2つである。

- **使う場面** — いつ・どんな対象に・何のために使うか。読み手はここで「この作業に当たるか」を判断する。
- **規則** — エージェントが作業中に従うこと。規則の形はスキルの性質で変わる。ツールをラップするスキルは、ツールが強制しない規則と、呼ぶコマンド・引数・出力の関係を載せる。規約を定めるスキルは、エージェントが守るべき規則だけを載せる。

選ぶ基準は「エージェントの操作に影響するか」である。エージェントが既に持つ言語・ツールの意味論と、ラップしたツールが実装する内部処理は、エージェントが操作するために知る必要がない。値と規則を所有する側（コード・設定・CLI）が持つものは、その側に置き、`SKILL.md`には判断の材料だけを載せる。

## 書き方

- **肯定形で書く** — 求められる振る舞いをそのまま書く。否定形は、その行為をエージェントの前に浮かべる。
- **操作に影響する詳細だけを書く** — エージェントは書かれた詳細をすべて操作へ反映しようとする。影響しない詳細は誤操作の原因になる。
- **自己説明するものは参照だけ** — 動きを自己説明するもの（CLIの`--help`等）があるなら、そちらへの参照だけを書く。

## 構成

`SKILL.md`を入口に、必要に応じて`scripts/`・`templates/`・`references/`を置く。規約を定めるスキルは`SKILL.md`だけでもよい。

| 置き場 | 内容 |
|---|---|
| `scripts/` | スキルがラップするツール。操作は各ツールの`--help`が自己説明する |
| `templates/` | エージェントがコピーして使う成果物の型 |
| `references/` | エージェントが持たない対象の深い知識。`SKILL.md`に収まらない場合にだけ置く |
