# スキルの書き方

スキルは、エージェントがいつ・なぜその作業を選び、作業中に何を守るかを伝える文書である。
`SKILL.md`は読み込まれるたびにトークンを消費し、判断にも影響する。
載せる内容は、エージェントが持たない知識と、従うべき規則のみに絞る。

## 載せる内容

`SKILL.md`に置くのは、次の3つである。

- **概要と使う場面** — いつ、どんな対象に、何のために使うか。
  descriptionに書く。
  読み手はここで「この作業に当たるか」を判断する。
- **背景** — どんな課題を解くか、何を改善するか。
  本文の目的に書く。
- **規則** — エージェントが作業中に従うこと。
  本文の進め方に書く。
  規則の形はスキルの性質で変わる。
  ツールをラップするスキルでは、ツールが強制しない規則と、呼ぶコマンド・引数・出力の関係を載せる。
  規約を定めるスキルでは、エージェントが守るべき規則のみを載せる。

載せるかどうかの基準は「エージェントの操作に影響するか」である。
エージェントが既に持つ言語やツールの意味論、およびラップしたツールが実装する内部処理は、操作のために知る必要がない。
値や規則を所有する側（コード・設定・CLI）に属する情報はその側に置き、`SKILL.md`には判断に必要な材料のみを載せる。

他のスキルへの参照は書かない。
参照の壊れに気づけないためである。
必要な知識は自分のスキルへ書き、他のスキルの発見はdescriptionに任せる。
スキル同士を関連付ける指示は、`AGENTS.md`などセッションへ常時注入されるファイルに書く。

## 見出し

本文はh1のスキル名で始まる。
h2は `このスキルの目的` と `進め方` を基本とし、`禁止事項` は例外的に置く。
h3以下は内容に応じて増やしてよい。

- **このスキルの目的** — どんな課題を解くか、何を改善するかを1〜3文で書く。
  descriptionには概要とトリガーだけを書き、背景を書かない。
  目的にはdescriptionの言い換えを書かない。
  背景が書けない場合は、スキルの要否かdescriptionの切り方を見直す。
- **進め方** — この作業に当たるときの指針（手順・注意点・判断基準）を書く。
  h2直後に方針を1文置き、その後に内容が分かるh3を、読む順・重要度順に並べる。
  長い参照情報は`references/`へ置き、進め方から参照する。
- **禁止事項** — 原則として置かない。
  肯定形で書けない規則、または禁止の集約そのものが情報になる場合にだけ置く。

本文のh1はスキル名とし、テンプレートとして載せる文書のh1はコードブロックや引用で本文の見出しと区別する。

## 書き方

- **肯定形で書く** — 否定形は避けたい行為をかえって意識させるため、求められる振る舞いを肯定形でそのまま書く。
  肯定形が禁止も含意するときは、肯定形のみで表す。
- **操作に影響する詳細のみを書く** — エージェントは書かれた詳細をすべて操作に反映しようとするため、影響しない詳細は誤操作を招く。
  操作に影響する詳細のみを書く。
- **自己説明するものは参照のみ** — 動きを自己説明するもの（CLIの`--help`など）は内容を重ねる必要がないため、そちらへの参照のみを書く。
- **任意の要素には条件と判定基準を持たせる** — 該当する場合のみ置く要素は、条件を欠くと必須と誤解されるため、定義側に条件（「該当する場合のみ」など）を書く。
  点検手順を持つスキルは、置くかどうかを判定する基準もチェックリストに置く。
- **定義と点検項目を整合させる** — 同じ規則を`SKILL.md`と`references/`のチェックリストの両方に書くと、片方の変更で矛盾するため、規則を変えたら両方を更新する。

## frontmatter

- `name`はスキルのディレクトリ名と一致させ、64文字以内にする。
  OpenCodeはディレクトリ名、Codexは`name`をスキルの識別子に使うため、食い違うとハーネスごとに呼び名が変わり、Codexは64文字を超える`name`を読み込まない。
  Agent Skills仕様は英小文字・数字・ハイフンに限るが、利用中のハーネスは日本語の`name`を読み込むため、日本語で名付ける。
- `description`は空にせず、Agent Skills仕様の上限である1024文字以内に収める。
  Codexは`description`が空のスキルを読み込まない。
- スキルを一時的に無効にするときは、`SKILL.md`を`.SKILL.md`へ改名する。
  どのハーネスも`SKILL.md`という名前のファイルだけを読むため、内容と履歴を残したまま読み込みから外せる。

## レビュー状態

`SKILL.md`のfrontmatterにある`metadata.user-review`は、人間のレビュー通過を示す。
編集するとレビュー結果は無効になるため、ユーザーから指示がない限り編集後は`false`へ戻す。

## 構成

`SKILL.md`を入口に、必要に応じて`scripts/`・`templates/`・`references/`を置く。
複数の作業にまたがる規約では、共通の判断を`SKILL.md`に置き、特定の作業だけで使う詳細を`references/`に置く。

| 置き場 | 内容 |
|---|---|
| `scripts/` | スキルがラップするツール。操作は各ツールの`--help`が自己説明する |
| `templates/` | エージェントがコピーして使う成果物の型 |
| `references/` | 対象の作業でだけ読む詳細な知識や規約 |
