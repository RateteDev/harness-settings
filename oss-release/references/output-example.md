# 成果物の見本

READMEとリリースノートの仕上がりは、次の公開リポジトリを手本にする。URLはいずれも`main`上のパスで参照し、作り直しても生きるようにする。

| 成果物 | 参照先 |
|---|---|
| README（既定言語） | https://github.com/RateteDev/chatgpt-auth-for-responses/blob/main/README.md |
| README（英語版） | https://github.com/RateteDev/chatgpt-auth-for-responses/blob/main/docs/readme/README.en.md |
| リリースノート | https://github.com/RateteDev/chatgpt-auth-for-responses/releases/tag/v0.1.0 |

## 写す観点

見本から写すのは、情報の並べ方と見た目の形式である。次を1つずつ点検する。

README:

- 先頭に中央寄せのヒーローを置く。ロゴ画像、バッジ、言語リンクの順に並べ、ロゴ画像が無い場合はタイトルを中央に置く。
- バッジと言語リンクは1行に2件ずつ並べる。
- タイトルの直後に、用途を一文で書く。
- できることを絵文字付きの箇条書きで並べる。
- 導入は最短の経路を先に示し、各コマンド行の直前にその行で起きることをコメントで書く。
- 利用者が最初に読む節の段落は短く（1段落2文まで）保ち、手順・挙動・制限は箇条書きにする。
- 性質の違う導線は節を分ける（例：画像を作る／ライブラリ／スキル）。
- GUIや視覚的な操作があるアプリでは、実画面のスクリーンショットを載せる。
- ライセンスは上部バッジと下部の見出し付きリンクの両方で示す。
- 開発者向けの内部手順（配布ワークフローの条件や資格情報の設定）を利用者向けの説明に混ぜない。

リリースノート:

- `『{サブタイトル}』をリリース！`の定型行で始める。
- その版の要点を伝える導入を置く。
- `## 🎉 新機能`などの見出しで分け、各項目を一文で書く。

## 写さない観点

見本の内容とプラットフォーム固有の要素は写さず、対象リポジトリの実態に合わせる。

- バッジの種類（見本はruntime Bunとlicense MIT）
- ロゴ画像の有無
- 言語版の有無
- 節の数と名前
- コマンドとその出力

## 点検の手順

1. 対象のREADMEとリリースノートを、GitHubの`POST /markdown`（mode: gfm）でHTMLへ変換する。
2. HTMLをローカルのヘッドレスブラウザで画像に描き出し、見本と並べる。
3. 「写す観点」を1つずつ確認する。見本に届かない観点を直す。写せない観点は理由を添えて残課題にする。
