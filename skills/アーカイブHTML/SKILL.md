# アーカイブHTML

## 目的

試行錯誤のプロセスや散逸しやすい素材を、**振り返り用HTML**と**作業原本zip**の2ファイルに集約・保存する。
人間とエージェントの双方が、後から同じ経緯と原本を迷わず確認できるようにする。

---

## 手順：アーカイブを作成する

「記録作成 → HTML化 → 原本zip化 → 検証・確認 → 作業フォルダ削除」の順に進める。
※ `md-render` コマンドが利用可能な環境を前提とする。
作業用ファイルは `/tmp` 配下に作成する。

### 1. `記録.mdx` を作成・検証する
[経過と記録](templates/経過と記録.mdx) のフォーマットに従い作成する。

- **構成・見出しルール**:
  - `h1`: `stepNN：名前`
  - `## 記録`
  - `### v タイトル`: 初期表示で展開するセクション
  - `### > タイトル`: 初期表示で折りたたむセクション
- **記述ルール**:
  - ログ・会話記録に基づき、「試したこと・分かったこと・判断理由」を客観的に書く。
  - ユーザーのフィードバックは発言のまま引用し、未解決事項は不明のまま残す。
  - 後から判明した知見は、当時の結果と明確に区別する。
  - コード等の丸写しは避け、判断の根拠となる要点のみを記載する。
- **MDX記法の注意点**:
  - コメント構文は使用しない。
  - 本文中の `{` や `<`（直後に大文字が続く場合）は、コードブロックにするか `\{`・`&lt;` とエスケープする。
- **検証**:
  ```bash
  md-render fix-spacing 記録.mdx
  md-render validate 記録.mdx
  ```

### 2. `index.mdx` を作成する
[index.mdx](templates/index.mdx) を `/tmp` にコピーして編集する。

- タイトルに `stepNN：名前` を設定する（`記録.mdx` のh1は含めない）。
- 成果物の図を `<Image>` コンポーネントで配置する。
- `記録.mdx` の `## 記録` 以降の内容を本文に貼り付ける。

### 3. HTMLを書き出す
メディアをインライン展開し、単一のHTMLを生成する。
```bash
md-render fix-spacing /tmp/index.mdx
md-render /tmp/index.mdx --out <名前>-アーカイブ.html --media inline
```

### 4. 原本zipを作成する
作業フォルダを圧縮する。
`記録.mdx` も必ず含める。
```bash
# node_modules や .git などを除外して圧縮
zip -r <名前>-原本.zip <作業フォルダ> -x "*/node_modules/*" -x "*/.git/*"
```

### 5. 整合性と安全性の確認
- `unzip` して `diff -r` を実行し、原本フォルダとzipの内容が一致することを確認する。
- APIキー等の機密情報が含まれていないことを確認する。

### 6. クリーンアップ
- ユーザーに成果物（HTML・zip）を確認してもらう。
- 承認後、ローカルの作業フォルダを削除する。

---

## 手順：アーカイブを読む

- **HTML（`<名前>-アーカイブ.html`）**:
  ブラウザでそのまま閲覧できる。
  成果物の図と、折りたたみ（h3）形式の経緯記録が1枚にまとまっている。
- **原本（`<名前>-原本.zip`）**:
  素材データやソースコードを確認したい場合は、同階層のzipを展開して参照する。
  記録のMDX原文は `記録.mdx` に含まれる。
