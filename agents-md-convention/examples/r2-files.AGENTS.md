# R2 Files

## 起きていた問題

Google Driveはエージェントからファイルを扱いづらく、所有者が使いたいUIも作りづらかった。
開発中に静的HTMLを作成して所有者がレビューする際には共有リンクを発行していたが、リンクを知る人なら誰でも閲覧できる形になっていた。
エージェントが示したファイルを、公開用の共有リンクを介さず所有者自身のアプリで開けるようにしたかった。

## 解決するための方針

R2をファイルの保存先とし、エージェントが使う`my-r2` CLIと、所有者が使うAndroidアプリから同じファイルを扱う。
エージェントが示した対象はアプリのディープリンクから開き、所有者が自分の認証情報で取得する。所有者自身のレビューに共有リンクの発行を要しない形を目指す。
AndroidアプリのUIは所有者の操作に合わせて作る。

## このリポジトリでの前提

現時点でAndroidアプリを使うのは所有者一人で、個人用APKは一般配布しない。将来はリポジトリをOSSとして公開し、アプリ内で接続先を設定できる配布版と、ソースから認証情報を埋め込む個人用ビルドの両方を提供したい。
現在の個人用APKから認証情報を抽出できることと、キー交換時に再ビルドすることは所有者が了承している。
実機検証はPixel 9aを対象とする。Pixel 10への所有者用APKの導入は、9aでの確認後に所有者が明示して依頼した場合に行う。

## インフラ・運用に関するコンテキスト

| 構成要素 | 状態 | 正となる定義 |
|---|---|---|
| R2認証情報 | 既存キーをビルド時に使用 | `~/.config/secrets.env` |
| APK署名鍵 | 更新時も同じ鍵を使用 | `~/.config/r2-files/release.jks` |
| Android SDK | ホストに導入済み | `ANDROID_HOME` |

## 常時遵守するべき制約

| 規則 | 理由 |
|---|---|
| 認証情報・署名鍵・APKはGit・CI成果物に含めず、除外済みのローカル出力に保存する。 | 秘密情報や所有者用APKの意図しない公開を防ぐため。 |
| 実機コマンドは対象シリアルを明示し、通常はPixel 9aを指定する。 | 普段使いのPixel 10もADBに接続されるため。 |
| GitHub Actionsなどの外部CIを追加せず、CIはローカルの`just ci-local`で実行する。 | 検査をローカルで完結させるため。 |
| Androidアプリの新規自動テストはunitテストに限り、UI操作は実機で確認する。 | UIの操作体験は実機で確認するため。 |
| R2の書き込みテストは承認済みの`tmp/r2-files-tests/`配下に実行ごとの専用領域を作り、その領域だけを操作・清掃する。既存データは読み取りだけで検証する。 | 既存の個人データをテストで変更しないため。 |
| お気に入りや最近使ったファイルは追加前に所有者へ相談する。 | 一覧を簡潔に保つため。 |
| 設定の操作ラベルは「キャッシュをクリア」のように簡潔な常体・句点なしで記述する。 | 操作を短く識別できるようにするため。 |
