# 指示書のチェックリスト

サブエージェントが対象の `AGENTS.md` を読み、書き方が規約に沿っているか、および表の記述がソースと一致しているかを判定するための観点である。

問題・方針・前提が事実として妥当かは所有者にしか判断できないため、検査対象にしない。

## 指示

以下を読んでから判定する。

- 対象の `AGENTS.md`
- 対象へ適用される上位の `AGENTS.md`（重複の照合用）
- タスクランナーのコマンド一覧（重複の照合用）
- 対象で利用可能な各 `SKILL.md`（スキルが持つ領域の確認用）
- インフラ表・制約表が名指しするファイル（突き合わせ用）

指摘は「行 → 該当する観点 → 移動先または直し方」の表で返す。修正はせず、`AGENTS.md` の変更は所有者の判断に委ねる。指摘がなければ、その旨を一文で返す。

## 文体

- [ ] 一読して意味が取れ、後置修飾が二段以上重なった文がない
- [ ] 比喩・擬人化・警句がなく、事実と帰結が平叙文で書かれている
- [ ] 段落が接続詞でつながり、短文をぶつ切りに並べただけの段落がない
- [ ] 表のセルで主語が省かれていない
- [ ] 英語からの不自然な直訳調がない

## 置き場違い

各行について「この情報は別の場所で得られるか」を問う。

- [ ] `ls` や設定ファイルから復元できる構成の写しがない
- [ ] タスクランナーのコマンド一覧と重複する説明がない
- [ ] スキルが持つ領域の規則を `AGENTS.md` にも書いていない
- [ ] 適用される上位の `AGENTS.md` と同じ規則がない
- [ ] 他文書の内容や役割を説明せず、必要なパスだけを示している
- [ ] 日付付きの進捗や作業ログがない
- [ ] 特定の関数・ファイルを触る時だけ必要な理由がない。該当する場合は実装側コメントへの移動候補とする
- [ ] 特定のディレクトリを触る時だけ必要な規則がない。該当する場合はそのディレクトリ直下の `AGENTS.md` への移動候補とする
- [ ] 特定の操作の瞬間だけ必要な手順がない。該当する場合は動的な指示注入への移動候補とする
- [ ] 捨てたものや没案の一覧がない。該当する場合は ADR またはコミットへの移動候補とする

## 章構成

- [ ] `起きていた問題`・`解決するための方針`・`このリポジトリでの前提`・`インフラ・運用に関するコンテキスト`・`常時遵守するべき制約` の 5 章が、この名前と順序でそろっている
- [ ] h1 の直下に要約文がない
- [ ] `起きていた問題` に、何を試して具体的にどこで困ったかがあり、製品ビジョンを問題の形に言い換えただけの文がない
- [ ] `このリポジトリでの前提` の各項目が、後段のいずれかの制約を正当化している
- [ ] `インフラ・運用に関するコンテキスト` が表であり、マシン側とリポジトリ外の状態だけを書いている

## 制約の各項目

- [ ] `規則 | 理由` の 2 列の表であり、理由の空欄がない
- [ ] 規則を破ったコードがコンパイルやテストを通る。機械が止める規則は書いていない
- [ ] `MANDATORY:` や `MUST` などの強度語がない
- [ ] 否定形に代替が添えられている
- [ ] 同じ内容を別の行や前提章と二重に書いていない

## ソースとの突き合わせ

- [ ] インフラ表の各行について、名指しされたファイルを開き、記述と一致するか確認した。存在しないユニット・イメージ・パスへの言及は指摘する
- [ ] 制約表が名指しするパス・レシピ・環境変数が実在する
