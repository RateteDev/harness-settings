# model-allowlist

## いつ

三つの契機で動く。
一つ目はプラグインの起動時で、状態ファイルを読み込み、モデルカタログを組み立てる処理に絞り込みの変換を登録する。この変換は、起動時の組み立てに加えて、再読み込みが要求されるたびに実行される。
二つ目は状態ファイルが外部から書き換えられたときで、変更を検出してカタログを組み立て直す。
三つ目は利用者がプロンプトを送信したときで、受け付ける前に状態ファイルを読み直し、更新の失敗があれば会話へ通知する。

変換は、全プロバイダーの全モデル（モデルID、プロバイダーID、有効かどうか）の一覧を受け取り、モデルをカタログから除去できる。
通知には、モデルの応答を起動しない擬似メッセージを会話へ差し込む能力が要る。

## 何をする

Web UIで選べるモデルをサーバー側の一つの状態ファイルで管理し、同じサーバーへ接続するすべての端末に同じ選択肢を見せる。
Web UIのモデル表示設定は端末ごとに保存されるため、複数の端末から接続しても選択状態を共有できなかったことが背景である。

状態ファイルはJSONで、バージョン、管理対象のプロバイダーIDの一覧、許可するモデルの一覧、確認済みのモデルの一覧を持つ。モデルは「プロバイダーID/モデルID」の形式で表す。
変換では、管理対象のプロバイダーに属し、有効で、確認済みの一覧にまだないモデルを、許可と確認済みの両方の一覧へ自動で加える。
そのうえで、管理対象でないプロバイダーのモデルと、許可の一覧にないモデルをカタログから除去する。管理対象でないプロバイダーのモデルは一件も残らない。
新しく現れたモデルは自動で使えるようになる一方、利用者が許可から外したモデルは確認済みに残るので、自動では許可に戻らない。

状態ファイルが存在しない初回の起動では、その時点のモデル一覧に現れたすべてのモデルを許可かつ確認済みとして登録し、それらのプロバイダーを管理対象にしてファイルを作る。
初回に一覧に現れなかったプロバイダーは管理対象にならない。
自動許可で状態が変わったときだけファイルへ保存する。
ファイルの変更を検出したときは、読み直した内容がメモリ上の状態と異なるときだけ、状態を差し替えてカタログを組み立て直す。

除去前の全モデルの正本は公開カタログ（https://models.opencode.ai/api.json）で、ハーネスが返すモデル一覧は除去後のカタログである。
除去前の全モデルが必要な処理を足すときは、ハーネスの一覧ではなくこの公開カタログを参照する。

## 調整値と根拠

状態ファイルの名前はmodel-allowlist.jsonで、ハーネス用の設定ディレクトリ（環境変数XDG_CONFIG_HOMEがあればその値、なければホームディレクトリ直下の.config）の中に置く。
読み込み時の検証は厳密で、バージョンが1であること、プロバイダーIDが重複のない文字列で「/」と「#」を含まないこと、モデルIDが重複のない文字列で「/」を一つ以上含み「#」を含まないことを確認する。
数値の閾値や上限は持たない。
置き場所と名前、検証の形式、ファイルの権限を所有者のみにしたことの理由は、根拠の記載なし。

## 失敗時の扱い

失敗は、会話への通知とログの二経路で伝える。
保存に失敗したとき、変更検出後の再読み込みに失敗したとき、プロンプト送信時の読み直しで状態ファイルが無いか読み取れなかったときに、失敗を記憶する。保存と再読み込みの失敗はログにも出す。
記憶した失敗があるときは、次のプロンプト送信時に擬似メッセージを会話へ差し込む。内容は、モデルの許可リストを更新できなかったこと、その理由、現在の許可状態を確認すること、この失敗を回答で利用者に伝えることをモデルに求めるものである。
同じセッションで同じ失敗を繰り返しても通知は一度だけで、後続の保存または再読み込みが成功した時点で失敗を解除する。
通知の差し込みに失敗したときは、プロンプトの受付を止める。

再読み込みに失敗したときはメモリ上の状態を直前の値へ戻すので、絞り込みは最後に成功した状態のまま続く。状態ファイルが削除された場合も同様である。

起動そのものが失敗する場合がある。状態ファイルの内容が不正なとき、初回の作成に失敗したとき、カタログを操作する仕組みが使えないときである。
このとき会話への通知は未対応で、起動に失敗するとフックが残らず、通知にはハーネス側のプラグイン失敗状態との連携が必要だとソースのTODOにある。
起動に失敗したときに絞り込みが適用されないのか、どのモデルが表示されるのかは、不明である。
