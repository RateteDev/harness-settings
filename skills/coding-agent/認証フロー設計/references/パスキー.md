# パスキー

## ライブラリ

`@simplewebauthn/server`と`@simplewebauthn/browser`を使う。
Cloudflare Workersでの動作は公式に書かれていないため採用前に試す。

## 名前の欄

管理ソフトはサービス名とアカウントを次の欄から表示する。
`rp.name`と`user.displayName`にはサービス名を入れ`user.name`には連絡先メールを入れる。

| 欄 | 値 | 表示される場所 |
|---|---|---|
| `rp.name` | サービス名 | 1Passwordの項目名 |
| `user.displayName` | サービス名 | Androidの保存画面のアカウントの1行目 |
| `user.name` | 連絡先メール | Androidの保存画面の2行目と1Passwordのユーザー名 |

表示先は2026年11月にAndroidのFirefoxと1Passwordで確かめた。

## 登録の設定

`user.id`は個人情報を含まない32バイトの乱数とする。
`residentKey`は`required`とし`userVerification`は`preferred`とし`attestation`は`none`とする。

## 作成とログイン

パスキーは連絡先メールを確かめた後に作り作った時点で本登録とする。
ログインは空の`allowCredentials`をボタンから渡しConditional UIは使わない。
未知の資格情報でログインされたら`signalUnknownCredential()`を呼ぶ。
ログインと削除のたびに`signalAllAcceptedCredentials()`を呼び空の一覧では呼ばない。
Signal APIはFirefoxが未対応のため関数があるときだけ呼ぶ。

## 検証

UVフラグのない応答は拒否する。
同期されるパスキーは署名カウンタに0を返し続けるため保存値と応答がともに0なら比べない。

## 管理画面

パスキーごとにカードを出し名前と作成日時と最終利用日時と削除を置く。
名前はAAGUIDからFIDO Metadata Serviceで提供元を調べて付け分からなければOSとブラウザの名前にする。
`passkey-authenticator-aaguids`は2027年1月に空になるため使わない。
