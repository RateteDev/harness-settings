# systemdユーザーユニット管理規約

## 目的

常駐プロセスや定期タスクを `systemd --user` で管理し、ホスト再起動時の自動復旧、障害監視、Discord通知、状態の復元を可能にします。

## 主な操作

ユニットの生成や管理には専用スクリプトを使用します（詳細は各コマンドの `--help` を参照）。

| 用途 | コマンド | 補足 |
|---|---|---|
| 常駐サーバーの登録 | `user-unit add standing` | Webサーバー等の常駐プロセス |
| 定期実行タスクの登録 | `user-unit add oneshot` | serviceとtimerの2ファイルを生成 |
| 診断・削除・再起動 | `user-unit doctor` / `uninstall` / `restart` | 既存ユニットの保守 |
| 独自ユニットの登録 | `user-unit check <file>`<br>`user-unit install <file>` | CLI引数で対応できない特殊設定用 |

---

## 設計原則

1. **アプリとホストの責務分離**
   - **リポジトリ（アプリ）側**: `just serve` や `npm start` などの単一の起動コマンドのみを提供します。
     systemdユニット定義はコミットしません。
   - **ホスト側**: 対象コマンドを常駐化するかどうかを判断し、ユニット定義を `~/.config/systemd/user/` に配置します。
     現在の運用メモはプロジェクトの `AGENTS.md.local` に記録します。

2. **手動作成・直接編集の禁止**
   - ユニットの生成・検証・配置は必ず `user-unit` コマンドを経由して行います。
   - スクリプトが付与する生成元メタデータ（ヘッダーコメント）により、衝突防止と確実なアンインストールを実現します。

3. **パスの指定ルール**
   - ユーザーホーム直下の固定パス: `%h` を使用（例: `%h/.local/bin/...`）。
   - リポジトリの作業ディレクトリ: ユニット生成時に解決した**絶対パス**を埋め込みます。

## 監視と障害通知

障害監視と通知はホスト共通のテンプレートユニットを利用し、関心を分離します。

| レイヤー | コンポーネント | 役割 |
|---|---|---|
| 実行 | 対象ユニット | プロセスの実行と再起動 |
| 監視 | `unit-failure-monitor@.service` | 初回異常の検知、10分後の継続確認、障害イベントの生成 |
| 通知 | `discord-notify@.service` | Discord WebhookへのEmbed送信（失敗時リトライあり） |

### 監視の配線ルール
- **常駐プロセス (`standing`)**: `all-stops`（意図しない停止すべて）を監視対象とします。
- **定期実行 (`oneshot`)**: `failures-only`（終了ステータス異常）のみを監視対象とします。

### 通知条件（ノイズ削減）
- 障害発生から**10分経過後も停止中、または再起動ループ（CrashLoop）が継続している場合のみ** Discord通知が送信されます。
- 一時的なエラーですぐに自動復旧した場合は通知されません。

## 秘匿情報（環境変数）の扱い

- 環境変数はホスト上のファイルにまとめ、ユニット側から `EnvironmentFile=` で読み込みます。
- **権限**: 秘密ファイルのパーミッションは必ず `600`（所有者のみ読み書き可）とします。
- **フェイルセーフ**: 秘密ファイルが存在しない場合はユニットを起動失敗させ、設定不備を早期検知します。
- **セキュリティ**: `user-unit` コマンドで検証する際、シークレットの中身は出力せず、ファイルの存在と権限のみを検証します。
