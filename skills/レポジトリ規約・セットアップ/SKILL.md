# レポジトリ規約・セットアップ

## このスキルの目的

リポジトリごとに構成を手作りすると、置き場や作業の前提がリポジトリ間で変わり、エージェントも人も毎回構成を読み解き直すことになる。
言葉で言える方針だけを揃え、細部は各リポジトリの言語やスタックに合わせて組み立てられるようにする。

## あるべき状態

- リポジトリはモノレポにし、アプリケーションは`apps/`、共有ライブラリと内部パッケージは`packages/`に置く。
- 設計判断は`docs/adr/`、仕様書は`docs/spec/`に置く。
- 開発コマンドの入口はリポジトリのルートの1か所にし、手元とCIで同じコマンドを使う。
- ツールチェーンの版は各言語の標準の置き場だけで宣言し、CIやビルドの設定には版を直接書かずにそのファイルから読ませる。
  Bunの版は`package.json`の`packageManager`に書く。
  Cloudflare Workers BuildsがBunの版として読むのは、この欄と環境変数だけであるためである。
- Gitフックは`.githooks/`に置き、`core.hooksPath`を`.githooks`に設定して有効にする。
  `core.hooksPath`はクローンごとの設定で引き継がれないため、クローンした後に設定する。
- 各リポジトリに、そのリポジトリの事実に基づいた`AGENTS.md`を置く。
