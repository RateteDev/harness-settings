# アーカイブHTML

## このスキルの目的

試行錯誤の経過は、記録と図を1つのHTMLにまとめないと後から追えず、素材も散逸する。
振り返り用のHTMLと作業フォルダのzipの2ファイルに揃え、人とエージェントが同じ原本から経過を確認できるようにする。

## あるべき状態

### 成果物

- 成果物は`<名前>-アーカイブ.html`と`<名前>-原本.zip`の2ファイルで、同じ名前を使って隣に並んでいる。
  ファイル名の「アーカイブ」が、この形式であることの目印になるためである。
- HTMLは、図とメディアを埋め込んだ単一ファイルで、そのままブラウザで読める。
- HTMLのタイトルは`stepNN：名前`で、記録のh1は含まない。
- HTMLの本文は、成果物の図を`<Image>`で並べた後に、`記録.mdx`の`## 記録`以降が続く。
- zipは作業フォルダ全体を収め、`記録.mdx`を含み、`node_modules`や`.git`のような再取得できるものを含まない。
- zipを展開した中身が作業フォルダと一致している。
- HTMLとzipに、APIキーなどの秘密情報が含まれていない。

### 記録

- `記録.mdx`は[経過と記録](templates/経過と記録.mdx)の型に沿い、h1（`stepNN：名前`）、`## 記録`、段階ごとの折りたたみh3の順に見出しがある。
  h3は、開いて始まる節を`### v タイトル`、閉じて始まる節を`### > タイトル`で書く。
- 記録は、確認できる記録・ログ・会話に基づき、何を試し、何が分かり、どう判断したかを書いている。
- ユーザーの評価は、そのときの言葉のまま引用されている。
- 不明な点は、不明と書かれている。
- 整理の段階で新たに分かったことは、当時の検証結果と区別して書かれている。
- ソースは写さず、判断の根拠に必要な箇所だけが書かれている。
- 本文の`{`と、大文字が続く`<`は、`\{`・`&lt;`かコード表記になっていて、MDXのコメント構文は使われていない。
- `記録.mdx`は`md-render fix-spacing`と`md-render validate`を通っている。
- 画像生成でデザイン案を作った場合は、[画像生成によるデザインの試行錯誤](references/imagegen-design.md)が求める再現材料が作業フォルダにある。
  画像生成を使ったときに読む。

## 守る順序

1. HTMLとzipを作り、zipの中身の一致と秘密情報が無いことを確かめる。
2. ユーザーに成果物を確認してもらう。
3. ユーザーの確認を得てから、作業フォルダをローカルから削除する。
   削除は取り消せず、zipに漏れがあると原本が失われるためである。

## 手段

### 作る

`md-render`コマンドを前提とする。
作業用の`index.mdx`は、[index.mdx](templates/index.mdx)を`/tmp`へコピーして記入する。

```sh
md-render fix-spacing 記録.mdx
md-render validate 記録.mdx
md-render fix-spacing /tmp/index.mdx
md-render /tmp/index.mdx --out <名前>-アーカイブ.html --media inline
zip -r <名前>-原本.zip <作業フォルダ> -x "*/node_modules/*" -x "*/.git/*"
```

zipの一致は、`unzip`で展開した中身と作業フォルダを`diff -r`で比べて確かめる。

### 読む

- HTMLの本編は図と記録である。
  記録の節は折りたたみh3で、`### v`の節は開いた状態から始まる。
- 素材の原本は、隣の`<名前>-原本.zip`を`unzip`して読む。
  記録の原文は、zip内の`記録.mdx`である。
