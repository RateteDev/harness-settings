# スキルの書き方

スキルは、エージェントがいつその作業に当たり、作業の結果として何が成り立っていればよいかを伝える文書である。
エージェントはあるべき状態から手順を自分で組み立てられるため、`SKILL.md`には状態を中心に書き、手順は順序そのものに意味がある場合だけ書く。

## 載せるもの

`SKILL.md`に載せるのは、エージェントが持たない知識と、作業の結果が満たすべき条件だけである。
載せるかどうかは「書かなければエージェントの結果が変わるか」で決める。
言語やツールの一般的な知識、`--help`やコードを読めば分かること、あるべき状態から自然に導ける手順は載せない。

- 概要と使う場面は、frontmatterの`description`に書く。
- 解く課題と狙いは、本文の「このスキルの目的」に書く。
- 作業の結果が満たすべき条件は、本文の「あるべき状態」に書く。
- 順序・承認・不可逆な操作の関門そのものに意味がある場合だけ、「守る順序」を書く。
- 状態が分かっていても知らなければ辿り着けない知識がある場合だけ、「手段」を書く。

他のスキルへの参照は書かず、他のスキルの発見は`description`に任せる。
参照が壊れても気づけないためである。
スキル同士を関連付ける指示は、`AGENTS.md`のように常時読み込まれるファイルに書く。

## 本文の構成

本文はh1のスキル名で始め、h2を次の順に置く。
「守る順序」と「手段」は、該当する場合だけ置く。

```markdown
# {スキル名}

## このスキルの目的

## あるべき状態

## 守る順序

## 手段
```

- **このスキルの目的**は、どんな課題を解き、何を良くするかを1〜3文で書く。
  `description`の言い換えにしない。
- **あるべき状態**は、作業の結果として成り立つべきことを、確かめられる言い切りの箇条書きで書く。
  観点が複数あればh3で分ける。
  各項目は、そのまま点検に使える形にする。
  理由が無いと例外扱いされやすい項目には、理由を同じ項目に添える。
- **守る順序**は、順序を崩すと取り返しがつかない、または承認や独立した判定を経ることに意味がある手順だけを番号付きで書く。
  なぜその順序なのかを添える。
- **手段**は、使うコマンドの形、ツールの癖、参照先など、エージェントが自力では辿り着けない知識だけを書く。
  `--help`が自己説明するものは参照だけにする。

あるべき状態が点検項目を兼ねるため、別のチェックリストは置かない。
ただし、別のエージェントに渡して判定させるチェックリストや、スクリプトが出力する点検の手引きのように道具として使う文書は、`references/`に置いてよい。
その場合も項目は言い切りで書き、`SKILL.md`の状態と食い違わないようにする。

## 書き方

- 文体は常体で書き、一文を一行にする。
- 肯定形で書く。
  否定形は避けたい行為をかえって意識させるため、求める状態をそのまま書く。
- 任意の要素には、置く条件（「該当する場合のみ」など）を書く。
- 長い参照情報は`references/`へ置き、本文からいつ読むかを添えて参照する。
- 強調は句点の前で閉じる。
  句点で改行する整形が、強調の内側の句点で改行して強調を壊すためである。

## frontmatter

- `name`はスキルのディレクトリ名と一致させ、64文字以内にする。
  OpenCodeはディレクトリ名、Codexは`name`をスキルの識別子に使うため、食い違うとハーネスごとに呼び名が変わる。
  Agent Skills仕様は英小文字・数字・ハイフンに限るが、利用中のハーネスは日本語の`name`を読み込むため、日本語で名付ける。
- `description`は空にせず、Agent Skills仕様の上限である1024文字以内に収める。
  Codexは`description`が空のスキルを読み込まない。
- `metadata.user-review`は、人間のレビュー通過を示す。
  編集するとレビュー結果は無効になるため、ユーザーから指示がない限り編集後は`false`へ戻す。
- `metadata.labels`は、スキルの性質を人が見分けるためのラベルで、`[規約, 使い方]`のようなリストで書く。
  値は次の3語に限り、両方が主要な中身である場合だけ2つ付ける。
  スクリプトを同梱しているだけで「使い方」を付けると、ほぼすべてに付いて見分けに使えなくなるためである。
  - 規約：成果物や操作が満たすべき状態を定めている。
  - 使い方：特定のCLIやスクリプトを正しく使うことが、主な中身になっている。
  - 考え方：成果物の形ではなく、設計や進め方の判断の拠り所を定めている。
- スキルを一時的に無効にするときは、`SKILL.md`を`.SKILL.md`へ改名する。
  どのハーネスも`SKILL.md`という名前のファイルだけを読むため、内容と履歴を残したまま読み込みから外せる。

## ファイルの置き場

| 置き場 | 内容 |
|---|---|
| `SKILL.md` | 入口。目的・あるべき状態と、該当する場合の守る順序・手段 |
| `scripts/` | スキルがラップするツール。使い方は各ツールの`--help`が自己説明する |
| `templates/` | エージェントがコピーして使う成果物の型 |
| `references/` | 特定の作業でだけ読む長い知識と、道具として使う点検文書 |
