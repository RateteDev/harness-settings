# PRF暗号化

運営者にもデータを読ませない暗号化（ゼロナレッジ）が求められたときに読む。

## 仕組み

パスキーのPRF拡張は、そのパスキーでしか得られない秘密の値を認証のたびに返す。
この値から鍵を作り、端末の中でデータを暗号化してから保存する。

## 決まり

- 暗号化の鍵はクライアントでPRFの出力から作り、サーバーへ送らない。
- データはマスター鍵で暗号化し、マスター鍵を各パスキーのPRF出力で暗号化（ラップ）して保存する。
- パスキーを追加・削除したらマスター鍵のラップを作り直す。
- Windows HelloがPRFに対応していないことを依頼者に伝える。
- すべてのパスキーを失うとデータを誰も復元できないことを利用者に明記する。
- Googleサインインだけの利用者は暗号化したデータを読めないため、暗号化を使う機能ではパスキーの登録を求める。
- エージェントやサーバーがデータを読む必要がある場合は、暗号化する項目と平文で持つ項目を分けて依頼者と決める。
