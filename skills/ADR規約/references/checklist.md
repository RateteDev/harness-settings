# ADRチェックリスト

作成者ではないエージェントが、対象のADRを検査するための点検項目である。

## 指示

- 対象のADRを読み、以下のすべての項目を判定する。
- 指摘は、項目ごとに「該当する項目 → 指摘箇所 → 直し方」の形で返す。
- ファイルは読むだけにし、修正は作成者に任せる。
- 判断の内容そのものへの異議は、指摘と分けて「作成者へ伝えるべき論点」として返す。
- 指摘が無ければ、その旨を1文で返す。

## 項目

### 対象

- [ ] 複数の選択肢から1つを選んだ判断であり、採らなかった選択肢を挙げられる。
  挙げられない場合は、ADRにする判断ではないと指摘する。
- [ ] 調査・検証の結果が、選んだ判断を裏付ける`根拠`として載っている。

### ファイル名と章構成

- [ ] ファイル名が`YYYYMMDD-hhmm-{h1のタイトル}.md`の形式で、タイトル部分がh1と完全一致している。
- [ ] h1はタイトル1つだけで、バッククォート・空白・`/`を含まない。
- [ ] h2は`背景`・`判断`の2つだけである。
- [ ] `背景`は、問題・試した経緯・検討に至った理由を2〜4文に収めている。
- [ ] `判断`には判断ごとにh3があり、各h3の直下に本文、`**根拠**`の順で置かれている。
- [ ] 各判断の採用・見送り・保留の結論が、h3直下の冒頭1〜2文で読み取れる。
- [ ] `根拠`は判断の決め手だけを書き、背景の再説明になっていない。
- [ ] 本文にfrontmatterと日付が無い。
  調査日時のようにタイムスタンプ自体が必要なものは除く。

### 書き方

- [ ] 常体で書かれている。
- [ ] 判断の材料になった数字と固有名（計測値・バージョン・HTTPステータス・外部ライブラリ名など）が具体値で残っている。
- [ ] 内部実装の関数名・定数名が判断の言葉に言い換えられている。
  識別子そのものが判断の対象である場合は除く。
- [ ] 地の文の1文は100字以内、箇条書きの1項目は80字以内・読点2つまでである。
  疑わしい文は文字数を数えて確かめる。
- [ ] 地の文の各文が対象とその理由・方法を同じ文に収め、条件や理由を接続して経緯を示している。
- [ ] 同じ事実・同じ数値が1か所にだけ書かれている。
- [ ] 本文は決定済みの事実と判断だけで構成され、予定・約束の表現や未決定の論点を含まない。
- [ ] 本文は対象の判断に関わる設計だけを扱っている。

### 図表

- [ ] 比較・一覧は表に、注意・制約・リスクは明示的な注記にまとめられている。
- [ ] 関係・流れ・収束など構造を持つ説明は、文章より先にmermaidで図示されている。
