# 認証手段の採否

依頼者に方針の理由を示すとき、または採否を見直すときに読む。

## 採否の一覧

| 手段 | 扱い |
|---|---|
| パスキー | 採用する |
| Googleサインイン | 採用する |
| Sign in with Apple | 原則として採用せず、iOSアプリでApp Store審査ガイドライン4.8に求められる場合だけ加える |
| メールOTP・メールのリンク | 採用せず、メールは連絡だけに使う |
| 認証アプリ（TOTP） | 採用しない |
| パスワード・回復コード | 採用しない |

## 採用しない理由

### メールOTP・メールのリンク

- アカウントの強さは最も弱い手段で決まるため、パスキーと並べるとフィッシングに強いパスキーの利点が失われる。
- NIST SP 800-63B-4はOTPをフィッシング耐性のない方式とし、メールを経路外認証に使うことを禁じている。
- メールでサインインできるとメールアドレスがアカウントの識別子になり、`sub`での紐付けと自動統合の禁止に反する。
- メールの不達や遅延がそのままサインインの障害になる。
- リンク方式は要求したブラウザに限定すればフィッシングに強いが、PCでサインインしスマホでメールを読む使い方では別端末用のコードに頼るためOTPと同じ弱さになる。
- claude.aiはGoogleとメールのリンクを主軸にしているが、パスキーを提供していないため下がる強さがなく、この構成の根拠にはならない。

### Sign in with Apple

- iPhoneの利用者はiCloudキーチェーンのパスキーでFace IDだけで登録できるため、Appleのボタンと同じ手軽さをパスキーで得られる。
- Webで使う場合も有料のApple Developer Programが必要だと複数の導入手順書が述べている（Appleの公式な明言は未確認）。
- 「メールを非公開」を選んだ利用者は中継用のアドレスになり、連絡先メールの扱いが増える。
- 審査ガイドライン4.8はGoogleなどを使うアプリに条件を満たす別のログイン手段を求めるが、Sign in with Appleを名指ししていない。
- アプリ自身のパスキーが4.8の別の手段に当たるかは未確認であり、iOSアプリでは審査の扱いを確かめてから採否を決める。

### 認証アプリ（TOTP）

- パスキーは単独で所持と生体認証またはPINの2要素を満たすため、重ねる意味がない。
- 6桁の入力方式でありフィッシングに弱い。
- スマホと一緒に失いやすく、パスキーの予備として働きにくい。
- Googleでサインインする利用者の保護はGoogleアカウントの2段階認証が担う。

### パスワード・回復コード

- パスワードは使い回しと漏えいの対象になり、フィッシングにも弱い。
- 回復コードは利用者が保管できずに失うことが多く、残ったもう一方の手段で回復する設計と役割が重なる。

## 判断に使ったデータ

| 出典 | 対象と時期 | 内容 |

| [Okta「Going Deep with Social Login」](https://www.okta.com/sites/default/files/2023-06/GoingDeepwithSocialLogin-Whitepaper-20230601-Final.pdf) | Okta・Auth0の世界の1か月分のログイン、2023年公開（Sign in with Apple公開直後の古いデータ） | ソーシャルログインのうちGoogleがログイン数の75%、Appleが14%、Facebookが7%である |
| [FIDO Alliance「Passkey Index 2026」](https://fidoalliance.org/passkey-index-2026/) | Google・Amazon・メルカリ・NTTドコモ・KDDI・LINEヤフーなど消費者向け15社、2026年9月集計 | 成功したサインインの36%がパスキーであり、パスキーの成功率は93%、従来の多要素認証は78%である |

| [Zenn（MAMORIO）](https://zenn.dev/iototaku/articles/619b8e14b1cb77) | 1アプリの直近2週間の登録者、件数非公開、2026年5月公開 | iOSではメール40.5%・Apple 31.9%・LINE 14.2%・Google 13.4%、AndroidではGoogle 32.0%・メール58.0%である |
| [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) | 2025年8月版 | 3.1.3.1でメールの経路外認証を禁じ、3.1.4と3.1.5でOTPをフィッシング耐性なしとする |
| [App Store審査ガイドライン 4.8](https://developer.apple.com/app-store/review/guidelines/) | 2026年10月16日更新 | 別のログイン手段の条件は、収集を名前とメールに限ること、メールを非公開にできること、同意なく広告目的で追跡しないことである |

LINEが日本で最大なのはLINE公式アカウントでの販促につなげるECの導入が中心であり、最小構成の認証という目的とは異なる。
日本のiOSではAppleやメールを選ぶ利用者が多いが、そのアプリはパスキーを提供しておらず、外したときにパスキーへ移るかはデータから分からない。

## 見直す条件

- AppleとメールがなくてもWebではパスキーが受け皿になるという見込みを前提にしており、数値の裏付けはまだない。
- 公開後は登録画面での離脱数と選ばれた手段を計測し、離脱が多い場合に採否を見直す。
- 利用者の多くがGoogleアカウントもパスキー対応の端末も持たないサービスでは、メールの採用を依頼者と個別に判断する。
