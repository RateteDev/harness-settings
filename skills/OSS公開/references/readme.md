# README作成ガイドライン

初見の利用者が「用途」と「最短の試し方」を即座に理解できるREADMEを作成してください。

---

## 1. 構成と執筆ルール

- **導入部**:
  - タイトル直後に「用途」と「対象者」を1文で簡潔に書く。
  - 主な機能は絵文字付きの箇条書きでまとめる。
  - 導入部の段落は2文以内とし、認知負荷を下げる。
- **導線と情報量**:
  - 最短で試せる手順のみを記載する。
  - 複数の導入方法や詳細な解説は、既存ドキュメントへのリンクに誘導する。
  - 「インストール」→「使い方」の順で記載する。
  - 成果物の配布が目的のリポジトリには開発用セクション（ビルド/テスト手順）を含めず、別ファイルに分ける。
- **コマンド例**:
  - 記載したコマンドが実際に動作することをリポジトリ内で確認する。
  - 各コマンドの直前に、実行内容を短くコメントする（補足は同一コメント内の括弧に書く）。
- **注意点**:
  - ユーザー影響のある制約（非対応フォーマット、自動終了条件など）のみを「注意点」セクションに短くまとめる。内部的な上限値などは記載しない。

---

## 2. ヒーローセクション（先頭部）

ページ先頭は中央寄せとし、上から**ワードマーク → バッジ → 言語リンク**の順で配置する。

1. **ワードマーク**:
   - フォント依存を防ぐため、文字をアウトライン化したSVGを作成し `assets/` に置く。
   - `<picture>` タグを使い、Light/Darkテーマを切り替える。
2. **バッジ**:
   - 配布先やリポジトリ状態を示すバッジを配置する（文言は事前にユーザーへ確認）。
   - 狭い画面での表示崩れを防ぐため、1行につき2件ずつ並べる。
3. **言語リンク**:
   - 先頭に `{既定言語} ・ English` の形式で配置する。

---

## 3. 図と画像

- **形式**:
  - Mermaidは使用せず、画像ファイルを使用する。
  - GUI操作がある場合は実際のスクリーンショットを配置する（手元にない場合はユーザーに提供を依頼し、実在する画像のみを参照する）。
- **内容の一致**:
  - 操作フローを示す図は、具体的な入出力や画面を描き、ソースコードの命名・表記と完全に一致させる。
- **アクセシビリティ**:
  - 図の内容は、本文または代替テキスト（alt属性）だけでも理解できるようにする。

---

## 4. 多言語対応とライセンス

- **配置パス**:
  - 既定言語版: リポジトリ直下の `README.md`
  - 英語版: `docs/readme/README.en.md`
- **ライセンス**:
  - 公開前にライセンスファイルを配置し、未定の場合はユーザーに確認する。
  - 上部にライセンスバッジを置き、下部の「ライセンス」セクションから該当条文へリンクする。

---
