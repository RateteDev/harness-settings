# systemd ユーザーユニット管理規約

## 目的

手動起動によるプロセス消失やサイレント障害を防ぎます。
unit の生成・監視・通知・シークレット管理を標準化し、ホスト障害時も構成を再現可能にします。

---

## 設計原則

### 1. 責務の分離と配置

- **アプリケーション**: `just dev` や `just serve` 等の起動インターフェースのみを提供し、永続化の判断はホスト側に委ねる。
- **リポジトリ**: unit ファイル自体はコミットせず、配備方法（バイナリ、Docker等）のヒントのみを残す。運用の記録は `AGENTS.md.local` に記載する。
- **ホスト**: unit 実体は `~/.config/systemd/user/` に配置する。このディレクトリを構成の正本（台帳）として扱い、ホスト再構築時は本スキルに従い再生成する。

### 2. unit の作成ルール

- **作成手順**: 一時ディレクトリで unit ファイルを作成・構文検証した後、`user-unit` コマンドで登録する。生成元を特定するヘッダーコメントを必ず含めること。
- **パスの記述**:
  - ホーム直下の固定パス: `%h` を使用
  - リポジトリや作業ディレクトリ: 生成時に解決した絶対パスを使用

### 3. 監視と通知

| レイヤー | 責務 |
|---|---|
| **対象 unit** | プロセスの起動・自動再起動 |
| **`unit-failure-monitor`** | 障害検知・10分後の状態再確認・原因分類・通知イベント発行 |
| **`discord-notify`** | Discord Embed の整形、送信、失敗時の再試行 |

- **配線ルール**:
  - 常駐サービス: `all-stops`（意図しない全停止を検知）
  - 定期実行（oneshot）: `failures-only`（異常終了のみを検知）
- **共通化**: 監視・通知 unit はホストに1組のみ配置し、テンプレートインスタンス（`%i`）で対象 unit 名を受け取る。
- **通知抑止**: 初回異常から10分経過後も停止中、または再起動ループが発生している場合のみ通知する（一時的な自己復旧は通知しない）。
- **検証**: 導入時は「自動復旧する一時障害」と「通知される継続障害」の両方を実テストで確認する。

### 4. シークレット管理

- シークレットはパーミッション `600` のホスト側ファイルに集約する。
- unit からは `EnvironmentFile=` で参照する。
- ファイル不在時は unit の起動を失敗させ設定不備を早期に露出させる。

---

## コマンド操作（`user-unit`）

各操作の詳細は `user-unit <subcommand> --help` を参照してください。

| 用途 | コマンド | 補足 |
|---|---|---|
| **常駐サービス登録** | `user-unit add standing` | ログアウト後も常駐 |
| **定期実行登録** | `user-unit add oneshot` | service と timer を一括生成 |
| **保守（点検・撤去・再起動）** | `user-unit doctor`・`uninstall`・`restart` | 状態確認やクリーンアップ |
| **カスタム unit 登録** | `user-unit check <file>` → `install` | CLI オプションで表現できない場合 |

※ `user-unit` はシークレットの値を画面表示せず、書式とパーミッションのみを検証します。
